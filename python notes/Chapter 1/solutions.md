## 🟡 Intermediate Solutions

1. **Source code** is the human-readable `.py` file you write. **Bytecode** is an intermediate, lower-level instruction set generated by compiling the source code — not readable machine instructions, but not plain text either. **Machine code** is the actual binary instructions the CPU executes; CPython's Virtual Machine translates bytecode operations into these on the fly.
2. The **PVM (Python Virtual Machine)** is the runtime engine that reads bytecode instructions one at a time and executes them, coordinating with the OS/CPU to perform the real work.
3. Because CPython **caches small integers** (typically -5 to 256) as shared objects for performance. `x` and `y` both point to the *same* cached `10` object in memory, so `id(x) == id(y)`.
4. **PyPy** — uses JIT (Just-In-Time) compilation, often much faster for long-running programs. **Jython** — runs on the Java Virtual Machine, allowing interop with Java libraries.
5. **PEP 8** is Python's official style guide, covering naming conventions, indentation, spacing, and layout. It matters because consistent style makes code easier to read and maintain across teams.
6. Because features that make Python easy to write (dynamic typing, an extra bytecode/PVM layer, automatic memory management) add overhead compared to compiling straight to machine code, but they save enormous developer time.
7. It means every piece of data you work with — including integers, strings, and functions — is represented internally as an **object**, with an identity, type, and value.
8. `print()` **displays** text to the console and returns `None`. `return` **sends a value back** to whatever called the function, so it can be stored or reused elsewhere in the program.
9. Example: building a **real-time video game engine** or **firmware for embedded hardware**, where Python's overhead and GIL make it a poor fit compared to C/C++/Rust.
10. The **Global Interpreter Lock (GIL)** — a mechanism ensuring only one thread executes Python bytecode at a time. Covered fully in **Chapter 27 - Multithreading**.

## 🔴 Advanced Solutions

1. Step by step: (1) You run `python3 script.py`. (2) CPython's compiler parses and compiles your source into bytecode. (3) The bytecode is loaded into the PVM. (4) The PVM executes each bytecode instruction, calling into the OS/CPU as needed (e.g., to write to the screen). (5) Any `print()` calls or other I/O produce visible output in your terminal.
2. CPython caches small integers as a **performance optimization** — avoiding repeated creation of the same tiny, extremely common objects. Relying on `is` (identity comparison) instead of `==` (value comparison) for numbers is risky because caching behavior isn't guaranteed for all integers (typically only -5 to 256) — outside that range, `x is y` may be `False` even when `x == y` is `True`, since each is a separate object in memory.
3. Compiled languages (C) translate all the way to native machine code ahead of time, generally running faster but requiring a separate compile step and more manual detail (memory management, types). Interpreted languages (Python) skip that upfront compile step for the developer and add convenience layers, trading some runtime speed for faster iteration. Example: a real-time flight control system → C (needs predictable, maximal performance). Example: a rapid internal automation script → Python (needs to be written and adapted quickly).
4. A **JIT (Just-In-Time) compiler**, as used by PyPy, analyzes code *while it runs* and compiles "hot" (frequently executed) code paths directly into optimized machine code on the fly, rather than always going through the bytecode-interpretation loop. This can make long-running programs significantly faster than standard CPython.
5. Because the performance-critical numerical work is usually delegated to libraries (NumPy, pandas) that are implemented in C/Fortran under the hood. Python acts as a convenient, readable "glue" language, while the heavy lifting happens in fast, compiled code.
6. A **`.pyc`** file is a cached, compiled bytecode version of a `.py` module, stored so Python doesn't have to recompile unchanged source files every time they're imported — speeding up subsequent runs.
7. The GIL prevents true parallel execution of Python bytecode across threads, so CPU-bound multi-threaded programs see little to no speedup from adding threads. I/O-bound programs (waiting on network/disk) are less affected because the GIL is released while a thread waits on I/O, allowing other threads to run during that wait.
8. Without `@dataclass`, you would need to manually write an `__init__` method to assign `self.name` and `self.age`, and possibly `__repr__` for readable printing — several extra lines of boilerplate that `@dataclass` generates automatically.
9. "Batteries included" refers to Python's extensive standard library that ships with the language itself, reducing the need for third-party packages for common tasks. Example modules: `os` (operating system interaction), `json` (working with JSON data), `datetime` (dates/times), `re` (regular expressions).
10. Interpreted/dynamically-typed languages often surface certain classes of errors (like type mismatches) **at runtime**, when that specific line actually executes, whereas statically-typed compiled languages often catch such errors **at compile time**, before the program ever runs — potentially catching bugs earlier in development.

## 🐞 Debugging Solutions

**1.** Missing colon `:` after the condition.
```python
if age > 18:
    print("Adult")
```

**2.** Python is case-sensitive; the built-in function is lowercase `print`, not `Print`.
```python
print("Hello")
```

**3.** The function body must be indented under `def`.
```python
def greet(name):
    print(f"Hi {name}")
```

**4.** Inconsistent indentation — `age = 28` is indented as if it's inside a block, but there's no block here.
```python
name = "Ada"
age = 28
```

**5.** `=` is the assignment operator; `==` is the equality comparison operator.
```python
x = 5
y = 10
if x == y:
    print("Equal")
```
